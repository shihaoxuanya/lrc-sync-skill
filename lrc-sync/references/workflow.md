# 校时方法与边界

## 为什么不能按歌曲总时长分配

总时长包括前奏、间奏、延长音和尾奏；一句的字数也不能决定演唱时长。旧时间轴的错误可能呈现为“越到结尾越拥挤”，这不是整体 offset 能解决的。特别要先检查最后一句何时开始、何时唱完，防止把数十秒尾奏误当成仍在唱词。

## 锚点记录

建议在工作目录保存 `anchors.md`：每个转场写出候选原音频秒数、原稿行号、依据和复核状态。锚点优先覆盖开头、首段主歌、重复副歌、桥段、最后一句和清屏点。锚点只是划分待核对区间，**不可对锚点之间所有句子做线性插值后宣称准确**。

首字可能是轻辅音，不一定在波形里形成高峰。声谱上持续的谐波可能来自乐器。混音中心声道不是人声分离。若已有可用人声分离工具，可以参考其结果，但时间轴必须回到原混音，并检查分离是否引入位移或截断。

## 自动转写与强制对齐

本项目没有内置识别模型、下载器、云端 API 或 GPU 依赖。环境提供的转写/强制对齐结果可用作候选；先检查其返回的时间戳单位和实际使用的录音。不要把较差识别文本覆盖原稿。反复副歌可能被合并或漏检，需以原稿计数校验。

自动结果不能证明真实歌词同步；没有实际测量依据时不要报告“95% 精度”或“误差 0.1 秒以内”。没有听音工具时直接说明，用声谱候选 + HTML 校对实现可交付闭环。

## 项目格式

```json
{
  "schema_version": 1,
  "title": "示例歌曲",
  "artist": "用户填写",
  "version": "实际录音版本",
  "duration": 12.0,
  "metadata": {},
  "entries": [
    {"time": 1.2, "text": "第一行原稿", "verified": false, "evidence": "spectrogram candidate"},
    {"time": null, "text": "第二行原稿", "verified": false, "evidence": ""}
  ]
}
```

`duration` 和 `time` 的单位都是秒，不是毫秒。`time: null` 是尚未确定，不等于零秒。`verified` 仅表示操作者宣称试听过，不是自动检测值。`audio_sha256` 记录原音频指纹，避免同名不同录音被误用。

## 整体或分段偏移

正数表示延后显示；负数表示提前显示：

```bash
python lrc-sync/scripts/lrc_tool.py shift project.json --seconds 0.35 -o shifted.json
python lrc-sync/scripts/lrc_tool.py shift project.json --seconds -0.20 --from-entry 8 --to-entry 18 -o segment-fixed.json
```

行号指时间轴项，从 1 开始，包含空白清屏项。偏移前项目应已完整打点。偏移若造成任何越界/重复/倒序，整次拒绝；不静默截断，也不删除重复。被改动项自动转回待复核。

## LRC 与播放器差异

工具接受 `[mm:ss]`、1–3 位小数和同一行多个时间标签，导出为 `[mm:ss.xx]`。百分秒精度只是文件表示，不代表实际校时达到 10 毫秒。多标签会展开到时间顺序，重复时间不会被静默删除。歌词与原稿比较应使用按演唱顺序写好的完整原稿。

对于非零 offset，导入默认要求明确其符号约定。选择 `positive-earlier` 会从每句时间减去 offset 毫秒；`positive-later` 会加上。导出统一烘焙时间并写 `[offset:0]`，减少播放器差异。

遇到“导入后似乎还是旧歌词”，检查播放器是否缓存、内嵌歌词是否覆盖外置文件、音频与 LRC 是否真正同名、文件是否误存为 `.lrc.txt`，再核实录音版本。不要直接认定都是播放器问题。

## 离线校对页

默认不包含音频，打开后选取本地文件。若项目有音频指纹且浏览器支持 SHA-256，会先检查指纹；浏览器不支持时会说明降级为时长核对。页面具有拒绝联网的内容安全策略，没有第三方脚本、统计或上传功能。

浏览器自动保存以生成页面的项目指纹区分。私密模式或禁用存储可能导致自动保存不可用，因此以导出的 JSON 为可靠备份。恢复 JSON 必须与本页面原始歌词、时长和音频指纹匹配；允许增加/删除空白清屏项，不允许恢复另一首歌。

按 M 或“打点并选下一句”只记录候选起点；仍需回听。时间改动后已复核状态会失效。完整导出拒绝缺失、重叠或越界时间。未复核行只能作为用户确认的草稿导出。
